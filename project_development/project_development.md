IPD 是 **Integrated Product Development**，中文叫 **集成产品开发**。它不是单纯的研发流程，而是一套把“市场、研发、制造、采购、财务、服务”拉到一起的产品开发管理体系。

它的核心思路有三点：

- **把产品开发当成投资**：每个阶段都要判断“值不值得继续投”，而不是立项后就一路干到底。
- **以市场为导向**：先搞清楚客户要什么、竞争格局怎样，再决定做什么产品。
- **跨部门并行开发**：研发、市场、制造、采购、财务等从早期就一起参与，减少后期返工。

### IPD 的六个阶段

| 阶段 | 主要回答 | 关键交付物 |
|---|---|---|
| 概念阶段 Concept | 值不值得做？ | 产品包需求、概念方案、初步业务计划 |
| 计划阶段 Plan | 怎么做？ | 产品规格书、概要设计、详细项目计划、最终业务计划 |
| 开发阶段 Develop | 把它做出来 | 详细设计、模块开发、样机、集成测试报告 |
| 验证阶段 Qualify | 做得对不对？ | 系统测试、Beta 测试、量产验证、认证报告 |
| 发布阶段 Launch | 怎么推向市场？ | 量产产品、营销物料、上市计划、渠道铺货 |
| 生命周期阶段 Lifecycle | 如何持续经营和退市？ | 经营分析、版本迭代、退市计划 |

### 两类关键评审点

IPD 里有两套“关卡”：

- **DCP：决策评审点**  
  由高层投资决策团队 IPMT 评审，判断项目是否继续、调整或终止。常见节点有：  
  - **CDCP**：概念决策评审，决定是否进入计划阶段；  
  - **PDCP**：计划决策评审，决定是否进入开发阶段；  
  - **ADCP**：可获得性决策评审，决定是否上市；  
  - **LDCP**：生命周期终止评审，决定是否退市。

- **TR：技术评审点**  
  由技术专家或跨部门团队评审技术方案是否成熟，例如需求是否清晰、架构是否可行、详细设计是否完成、样机是否达标、是否具备量产能力等。

简单说，**DCP 管“要不要投钱”，TR 管“技术上能不能做成”**。

### 关键组织角色

- **IPMT**：集成组合管理团队，负责投资决策和资源分配。
- **PDT**：产品开发团队，由研发、市场、制造、采购、财务、服务等代表组成，对产品商业成功负责。
- **LMT**：生命周期管理团队，负责产品上市后的运营、迭代和退市。
