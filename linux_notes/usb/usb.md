### 8. usb主机如何识别到usb设备被插入/拔出了?

## USB2.0协议中6种设备状态
1. 连接状态attached
    物理连接已建立。
2. 上电状态powered
    设备从 VBUS 获得供电。
    设备把 1.5kΩ 上拉电阻接到 D+ 或 D- 上
    此时主机通过检测电平变化得知设备被插入
    主机发送复位信号，D+、D- 同时拉低，形成 SE0，持续至少 10ms。
3. 默认状态default
    主机复位后，设备处于地址 0
4. 地址状态address
    主机分配了非零地址。
    usb设备地址是主机分配的
5. 配置状态configured
    主机发送 SET_CONFIGURATION 后进入该状态。
6. 挂起状态suspend
    总线空闲一段时间后进入低功耗状态。


## 展开讲下空闲,插入和拔出时的电平状态和变化
1. 对于usb2.0的低速设备
    host的D+和D-各有一个15K的下拉电阻，空闲时两条线都是低电平
    device的D-有一个1.5K的上拉电阻,设备插入后,D-数据线被拉高到约 3V
    主机看到 D- 被拉高，判断为低速设备插入。
2. 对于usb2.0的全速设备
    host的D+和D-各有一个15K的下拉电阻，空闲时两条线都是低电平
    device的D+有一个1.5K的上拉电阻,设备插入后,D+数据线被拉高到约 3V
    主机看到 D+ 被拉高，判断为全速设备插入。
3. 对于usb2.0的高速设备
    host的D+和D-各有一个15K的下拉电阻，空闲时两条线都是低电平
    device的D+有一个1.5K的上拉电阻,设备插入后,D+数据线被拉高到约 3V
    主机看到 D+ 被拉高，判断为全速设备插入。
    所以高速设备会被先识别为全速设备
    之后通过Chirp K/J 握手协议,再被确认为高速设备
    然后会设备将1.5k的上拉电阻断开启用 45Ω 高速终端电阻
    另外高速设备通信用的是电流模式,差分信号幅值约 400mV 级别
    高速设备拔出后，主机端终端电阻从 22.5Ω 变为 45Ω，差分信号幅值从约 400mV 升至约 800mV。Hub 在每个 MicroSOF 包结束时检测，若差分幅值 ≥ 625mV 则判定设备拔出。
4. 对于usb3.0的设备
    会先走 USB 2.0 的 D+/D- 枚举流程
    同时主机在 SuperSpeed 差分对上执行 Rx Detect
    主机通过检测 TX 线上电压上升/充电速率或 RC 时间常数的变化，判断对端接收终端是否插入/拔出。


### 9. OTG的主从设备切换
## Micro USB OTG接口
1. VBUS
2. GND
3. D+
4. D-
5. ID
    ID引脚是主从角色识别引脚。设备检测到插入的插头的ID为低时,设备作为Host并开启VBUS供电；检测到ID为高时作为Device，VBUS由外部主机提供。


Micro-A 插头：ID 在插头内部短接到 GND，设备检测到 ID=0，作为 Host，开启 VBUS 供电。
Micro-B 插头：ID 悬空，设备检测到 ID=1，作为 Device，VBUS 由对方提供。

旧手机如果想做主机接入U盘,要用Micro-A头的或者改造Micro-B 插头内部 ID 短接到 GND
旧手机如果想做从机接入电脑,要用Micro-B头



## Type-C OTG接口
Type-C 接口本身 没有 Micro USB 那种 ID 引脚。
它用 CC1 / CC2 引脚来做角色协商：

 
Source：供电方，比如充电器、电脑 USB-C 口
DFP：下行端口，通常对应Host侧。
Sink：受电方，比如手机、耳机。
UFP：上行端口，通常对应Device侧
Rp 上拉电阻 
Rd 下拉电阻
DRP = Dual-Role Port，双角色端口。

DFP/UFP 是 Type-C 的数据角色，Host/Device 是 USB 协议角色

Source/DFP/Host 端在 CC 上接上拉电阻 Rp
Sink/UFP/Device 端在 CC 上接 5.1kΩ 下拉电阻 Rd

DRP 设备，未连接时会周期性切换 Rp/Rd
切换到 Rp,检测到Rd接头,做Host/Source
切换到 Rd,检测到Rp接头,做Device/Sink

普通无芯片 Type-C 线缆里，CC 只是一根直通线,不会自己带 Rp 或 Rd

很多普通外设，比如 U 盘、键盘、鼠标，本身是 Type-A 接口，它没有 CC 引脚，也不会接 Rd,所以会用到Type-C OTG 转接头,Type-C OTG 转接头通常会在 CC 引脚上接 5.1kΩ 下拉电阻 Rd，让手机认为对方是一个 Device；如果手机本身支持双角色端口 DRP，就会切换成 Host 角色。

### 10. 主机如何识别usb设备的类型-描述符

## 描述符
描述符是一组标准化的数据结构,linux中用结构体表示
设备通过它向主机说明自己的能力。
主机通过 GET_DESCRIPTOR 请求从设备的默认端点 EP0 读取描述符,据此识别设备、匹配驱动、选择配置，并建立通信。

USB 描述符是分层结构：
1. 设备描述符
    - 只有1个
    - 描述设备整体信息：USB 版本、设备类、厂商 ID、产品 ID、设备版本、配置数量、EP0 最大包大小等。
2. 配置描述符
    - 一个设备可以有多个配置，但同一时间只能激活一个。
    - 描述供电方式、最大功耗、该配置下有多少个接口。
3. 接口描述符
    - 一个配置下可以有多个接口。
    - 接口通常对应一个功能，例如耳机里的音频播放、按键控制。
    - 一个接口还可以有多个接口设置 Alternate Setting，不同设置可能使用不同带宽或不同端点组合。
4. 端点描述符
    - 属于某个接口设置,有0个或者多个
    - 描述某个接口设置下非0端点的端点号、方向、传输类型、最大包大小、轮询间隔等。
    - 端点 0 是默认控制端点，每个设备都有，不归属于某个接口,用于枚举阶段通信。
    - 端点描述符中的传输类型字段可以是控制、批量、中断、等时 4 种之一；但非0端点通常使用批量、中断或等时，控制传输主要通过端点 0 完成。

设备、配置、接口、端点描述符是分层包含关系；实际读取时，主机通常通过配置描述符集合一次性获取配置、接口、类特殊描述符和端点描述符。


### 11. 四种传输模式

## 传输模式特点

1. 批量传输Bulk Transfer
   - 数据量大，可靠性高，实时性差。
   - 有应答，支持 CRC 校验和重传。
   - 只在总线空闲带宽可用时传输，优先级较低。
   - 典型设备：U盘、打印机、扫描仪。

2. 中断传输Interrupt Transfer
   - 数据量小，可靠性高，实时性强。
   - 有应答，支持 CRC 校验和重传。
   - USB 没有真正的设备主动中断信号，本质是主机按固定间隔轮询。
   - 典型设备：键盘、鼠标、游戏手柄。

3. 等时传输Isochronous Transfer
   - 数据量多，实时性强。
   - 没有应答，不支持重传，不保证数据一定可靠送达。
   - 主机为其预留固定带宽，适合连续流数据。
   - 典型设备：USB 摄像头、麦克风、扬声器。

4. 控制传输Control Transfer
   - 双向传输，数据量通常较小。
   - 有应答，可靠性高。
   - 所有 USB 设备必须支持，通过端点 0 完成。
   - 主要用于设备枚举、配置、命令下发和状态查询。

不管是 IN 还是 OUT，USB 通信都由主机发起。


### 12. USB的数据格式组成

## 组成
由域,包,事务,传输组成
多个域组成包,多个包组成事务,多个事务组成传输

1. 域Field,是 USB 数据的最小单位，由若干位组成。
    - 同步域SYNC：Synchronization Field用于时钟同步，标志包的开始。
    - 地址域ADDR：Address Field7 位，表示设备地址；地址 0 是枚举前的默认地址。
    - 端点域ENDP：Endpoint Field4 位，表示端点号。
    - 帧号域FRAM：11 位，用于 SOF 包，表示帧号。
    - 标识域PID：Packet ID表示包的类型和格式。
    - 数据域DATA：承载实际数据，长度随传输类型变化。
    - 校验域CRC：Cyclic Redundancy Check令牌包使用 CRC5，数据包使用 CRC16
2. 包Packet
    - 令牌包Token Packet
        - IN：主机请求从设备读取数据。
        - OUT：主机向设备写入数据。
        - SETUP：用于控制传输的建立阶段。
        - SOF：帧起始包，每帧开始时由主机发送，包含帧号。
        - PRE：前导包，用于低速设备通信。
        - SPLIT：分割事务包，用于高速 Hub 与低速/全速设备通信。
        - PING：用于批量 OUT 传输前查询设备是否准备好。
    - 数据包Data Packet
        - 携带实际数据，常见有 DATA0、DATA1，高速下还有 DATA2、MDATA。

    - 握手包Handshake Packet
        - ACK：确认接收成功。
        - NAK：暂时不能接收。
        - STALL：端点出错或不支持请求。
        - NYET：高速传输中使用的否定应答。
        - ERR：错误指示。
        
3. 事务Transaction,是 USB 通信的基本交互单位，由主机发起。
    - IN 事务：主机发 IN 令牌 → 设备发数据包 → 主机发握手包。等时传输的事务通常没有握手阶段。
    - OUT 事务：主机发 OUT 令牌 → 主机发数据包 → 设备发握手包,等时传输的事务通常没有握手阶段。
    - SETUP 事务：主机发 SETUP 令牌 → 主机发数据包 → 设备发 ACK。
4. 传输Transfer,是软件层面看到的一次完整通信任务
    前面讲到的控制传输,批量传输,中断传输,等时传输

### 14. USB 枚举

## 控制传输的三个阶段

控制传输由 3 个阶段组成：

1. 建立阶段 / Setup 阶段：固定使用 SETUP 事务。
2. 数据阶段 / Data 阶段：可选，用于传输实际数据。
3. 状态阶段 / Status 阶段：用于报告本次控制传输是否成功。

控制写传输：
  Setup 阶段：SETUP 事务
  数据阶段：多个 OUT 事务
  状态阶段：IN 事务

控制读传输：
  Setup 阶段：SETUP 事务
  数据阶段：多个 IN 事务
  状态阶段：OUT 事务

无数据控制传输：
  Setup 阶段：SETUP 事务
  数据阶段：无
  状态阶段：IN 事务

## SETUP 阶段

- 必须携带固定的 8 字节数据结构。
- 数据包必须使用 DATA0。
- 设备应答必须是 ACK。

## 数据阶段

- 数据阶段从 DATA1 开始。
- 之后 DATA0、DATA1 交替。
- 应答可以是 ACK，也可以是 NAK 或 STALL。

## 状态阶段

- 传输方向与数据阶段相反。
- 数据包必须使用 DATA1。
- 状态阶段发送的是零长度数据包。

## SETUP 的 8 字节数据结构

1. 字节 0：bmRequestType
   - Bit 7：方向
     - 0 = 主机到设备
     - 1 = 设备到主机
   - Bit 6-5：类型
     - 00 = 标准请求
     - 01 = 类请求
     - 10 = 厂商请求
     - 11 = 保留
   - Bit 4-0：接收者
     - 0 = 设备
     - 1 = 接口
     - 2 = 端点
     - 3 = 其他

2. 字节 1：bRequest，请求代码
   - 0：GET_STATUS，获取状态
   - 1：CLEAR_FEATURE，清除功能
   - 3：SET_FEATURE，设置功能
   - 5：SET_ADDRESS，设置地址
   - 6：GET_DESCRIPTOR，获取描述符
   - 7：SET_DESCRIPTOR，设置描述符
   - 8：GET_CONFIGURATION，获取配置
   - 9：SET_CONFIGURATION，设置配置
   - 10：GET_INTERFACE，获取接口
   - 11：SET_INTERFACE，设置接口
   - 12：SYNCH_FRAME，同步帧

3. 字节 2-3：wValue
   - 含义随 bRequest 变化。
   - 如果 bRequest 是 GET_DESCRIPTOR：
     - 高字节：描述符类型，如设备描述符、配置描述符、字符串描述符。
     - 低字节：描述符索引。

4. 字节 4-5：wIndex
   - 通常表示接口号、端点号或语言 ID。

5. 字节 6-7：wLength
   - 表示数据阶段要传输的字节数。
   - 为 0 表示没有数据阶段。

## 地址 0 与端点 0

枚举开始时，设备地址固定为 0，通信只能通过端点 0 完成。

## 枚举过程

1. 主机检测到设备插入，对端口执行复位。
2. 主机通过地址 0、端点 0 发送 GET_DESCRIPTOR，先读取设备描述符前 8 字节，获取 EP0 最大包长。
3. 主机通过地址 0、端点 0 发送 SET_ADDRESS，为设备分配新地址。
4. 主机使用新地址、端点 0 重新读取完整设备描述符。
5. 主机读取配置描述符集合，包括配置、接口、端点等描述符。
6. 主机可选读取字符串描述符。
7. 主机发送 SET_CONFIGURATION，激活设备配置。
8. 主机根据接口类码匹配驱动，设备进入可工作状态。
